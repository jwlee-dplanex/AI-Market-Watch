(A) **섹션 전체(면) 처리 — "이 구역 전체가 다른 층위"라는 신호.** 3장의 카드를 옅은 바이올렛→그린 그라디언트 워시 "트레이"(`bg-gradient-to-r from-primary/5 via-white to-accent/5`, `border-primary/15`) 위에 얹었다. 디자인 시스템의 Accent(그라디언트) 카드 (`docs/design.md` "1.5 컴포넌트 정의 › Card › Accent")가 쓰는 것과 동일한 브랜드 그라디언트 DNA(Violet→Green)를 재사용하되, **채도를 5% 알파로 낮춰 워시로만 썼다** — Accent 카드의 실제 예시는 REPORT-002 상세 헤더 하나뿐이고 거긴 카드 1장짜리 히어로 자리다. 대시보드는 이미 카드가 여럿(주요 이슈·최신 뉴스·핵심 지표 3장)이라 진한 Accent 카드를 그대로 3장 반복하면 "한 곳만 튀는 게 아니라 다 튀어서 서로 상쇄되는" 역효과가 난다고 판단해 채택하지 않았다 — 옅은 워시 트레이 위에 흰 카드를 얹는 절충으로 "떠 보이는" 효과만 취했다. 페이지 배경(`#F9F9F7`)과의 명도차가 흰 카드 단독보다 커서, 스크롤 없이 보이는 첫 화면에서 이 구역이 가장 먼저 눈에 들어온다. (B) **여백·구분선 — 아래 섹션과의 위계 차이.** 트레이 안쪽 패딩을 다른 카드(`p-5`)보다 넉넉한 `p-6`로 주고, 트레이 바깥 하단 여백을 `mb-6`(다른 섹션 간 표준 간격)이 아니라 `mb-8`로 넓혀 "주요 이슈 + 최신 뉴스"와 확실히 분리되는 한 호흡을 만들었다. 섹션 제목 옆에 Lucide `flame` 아이콘(`w-4 h-4 text-primary`)을 추가했다 — 기존 아이콘 규칙(카드 내부 18px 이내, 모노톤 라인)을 그대로 따르는 시각 신호이며, "가장 중요한" 같은 문구가 아니라 "이 구역이 하이라이트 구역"이라는 걸 도상으로만 전달한다("분석" 라벨 옆 `trending-up` 아이콘, "시사점" 옆 `lightbulb` 아이콘과 동일한 기존 관례). (C) **최상단 배치 자체가 가장 강력한 우위 수단.** 페이지 최상단(헤더 바로 아래, 스크롤 0에서 항상 보이는 자리)에 위치하는 것만으로 이미 "가장 먼저 보는 영역"이라는 목적은 절반 이상 달성된다 — (A)(B)는 그 위에 더하는 보강이다. "주요 이슈"와 구분되는 나머지 지점은 배치·크기다 — (1) "주요 이슈" 리스트 안에 중첩된 항목이 아니라 그 자체로 최상위 카드(주요 이슈/최신 뉴스 카드와 동급의 `p-5` 컨테이너, 리스트 항목의 `p-4`가 아님), (2) 3장이 나란히 놓인 별도 행으로 "주요 이슈 + 최신 뉴스" 2단 그리드 위에 위치, (3) 카드 왼쪽에 Primary Violet 강조 보더(`border-l-4`, 디자인 시스템 Callout "Info" 스펙 재사용 — 새 시각 요소를 만들지 않음). 순서(1·2·3)는 등급 배지·순위 숫자 없이 "위치로만" 드러낸다(headliner_order 오름차순, 좌→우 배치, PM 정책 7번) — 3장 모두 동일 크기(flex-1)이며 1번 카드를 더 크게 만들지 않는다. **이번 "눈에 띄게" 요청에 대응한 (A)(B)(C)는 전부 헤드라이너 영역 전체에 균등하게 적용했다** — 3장 중 특정 카드에만 강조를 주지 않았다. 영역은 도드라지되 그 안의 1·2·3은 경쟁하지 않아야 한다는 조건(2026-08-06 네 번째 사용자 요청)을 지키기 위함이며, 크기 차등을 두면 "1등 라벨"의 시각적 우회가 될 수 있다는 우려(PM 판단 요청 사항)를 원천 차단하는 기존 판단과도 일치한다. 아코디언 인터랙션(펼침/접힘, 분석·시사점·관련 기사)은 "주요 이슈" 카드와 100% 동일한 마크업을 그대로 복제했다 — 새 인터랙션을 만들지 않고, x-cloak도 동일하게 각 x-show 엘리먼트에 그대로 붙였다(FOUC 방지, CLAUDE.md 인터랙션 패턴 준수). 좁은 화면 대응: (2026-08-07)" 절 참고. 1. **레이아웃 — 가로 3열 → 세로 2행.** "드롭다운 열었을 때 세로가 너무 길고 불편하다"는 사용자 지적으로 `flex-col md:flex-row`(데스크톱 3열)를 전 구간 `flex-col`(항상 1열 세로 스택)로 바꿨다. 위 "좁은 화면 대응" 단락이 설명하는 `md:flex-row` 분기는 더 이상 없다 — 이제 모든 화면 폭에서 세로다. 2. **표시 건수 — 3건 → 2건.** `slice:":3"` → `slice:":2"`. **PM이 "상한(headliner_order 지정 상한)과 렌더 상한은 항상 같이 움직인다"고 명문화**했다 — 조항만 고치고 렌더 상한을 그대로 두면 안전장치가 조용히 무력해진다. 현재 지정 2건(Insight 46·13)이라 이번 변경으로 잘려나가는 카드는 없다. 3. **가로 stretch 버그가 자동으로 사라진다.** 위 "높이 정렬은 별도 처리가 필요 없다" 서술이 근거로 들었던 flex 기본 cross-axis stretch(가로 배치일 때 제목이 가장 긴 카드에 맞춰 나머지가 같은 높이로 늘어나는 현상, 빈 상자를 만드는 원인)는 주축이 세로로 바뀌면서 애초에 성립하지 않는다 — cross-axis(가로)는 폭 stretch일 뿐이고 그건 카드가 컨테이너 전체 폭을 쓰길 원하는 정상 동작이라 문제가 아니다. 별도 CSS 처리를 추가하지 않았다. 4. **시사점 블록 제거.** "관련 기사 제외하고 내용만 300자 말하는 거야" — 대시보드는 "무슨 일이 있었나"만, 시사점은 REPORT-002 몫으로 역할을 나눴다. `implication`/ `display_implication` 조건 분기를 통째로 지웠다. 관련 기사 목록은 그대로 유지한다 (건수를 줄이지 않는다 — 14건짜리 이슈도 그대로). 5. **펼침 본문 — 정본(`content`) → 축약본(`display_content`).** 접힌 상태 미리보기 (`line-clamp-2`)는 이번에도 손대지 않았다 — 사용자가 "펼치기 전은 괜찮다"고 명시했다. 6. **등급 배지 — 오늘 두 번 뒤집힌 결정.** 신설 당시엔 "배지 없음"이었다가(위 "개별 카드에 등급 배지... 붙이지 않는다" 서술), 사용자가 "헤드라인에 넣는 거면 주요 이슈에도 넣어야 하는 거 아니야?"로 뒤집어 **헤드라인·주요 이슈 양쪽 모두**에 동일한 배지를 추가했다(`docs/planning.md` 정책 ② 폐기). `grade`가 `unspecified`이면 렌더하지 않는다 — "미지정" 배지로 내부 상태값을 노출하지 않기 위함(PM 요청). 색상: 1급 `bg-primary/10 text-primary`, 2급 `bg-teal/10 text-teal`, 3급 `bg-gray-100
