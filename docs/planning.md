# AI Market Watch 기획 문서

## 1. 서비스 개요

AI Market Watch는 AI 시장 동향과 금융권 AI 활용 사례를 자동으로 수집하고 분석하여 전략기획팀이 시장 변화와 DPLANEX 사업 기회를 빠르게 파악할 수 있도록 지원하는 내부 웹 대시보드 서비스이다.

뉴스, 기업 블로그, RSS, API 등 다양한 데이터 소스를 기반으로 AI 관련 정보를 수집하고, LLM API를 활용해 뉴스 요약, 주제 분류, DPLANEX 관점 태깅, 유사 기사 기반 인사이트, 주간 AI 인사이트 보고서를 생성한다.

---

## 2. 추진 배경 & 문제 정의

AI 시장은 다양한 기술 흐름을 중심으로 빠르게 변화하고 있다. 전략기획팀은 이러한 시장 변화를 지속적으로 모니터링하고 DPLANEX 사업 방향과 연결해 해석할 필요가 있다. 그러나 기존 방식은 담당자가 직접 뉴스를 검색하고 문서로 정리하는 수작업 중심이어서 정보 수집과 정리에 많은 시간이 소요된다.

기존 AI 시장 정보 수집 방식의 한계:

- 담당자가 직접 검색하고 정리해야 하므로 시간이 많이 소요된다.
- 기사와 자료가 개별적으로 관리되어 유사 이슈나 시장 흐름을 파악하기 어렵다.
- 조사자마다 분류 기준과 해석 관점이 달라 일관된 인사이트를 만들기 어렵다.
- 수집된 뉴스가 실제 DPLANEX 사업 기회와 어떻게 연결되는지 파악하기 어렵다.
- 정기적으로 공유 가능한 보고서 생성 과정이 수작업에 의존한다.

AI Market Watch는 반복적인 시장 리서치 업무를 자동화하고, 단순 뉴스 요약을 넘어 DPLANEX 관점의 시사점과 사업 기회를 도출하기 위해 추진한다.

---

## 3. 핵심 가치

1. **AI 시장 정보 수집 자동화** — 뉴스, 기업 블로그, RSS, API 등 다양한 소스를 기반으로 AI Agent, 생성형 AI, AX, 금융권 AI 활용 사례를 자동 수집한다.
2. **뉴스 요약 및 주제 분류 자동화** — 수집된 정보를 LLM API로 요약하고, 기술 흐름·기업 사례·금융권 활용·규제·경쟁사 동향 등으로 분류한다.
3. **유사 기사 검색과 이슈 그룹핑** — 개별 기사 단위가 아니라 유사한 이슈를 묶어 시장 흐름과 반복적으로 등장하는 주요 주제를 파악할 수 있도록 지원한다.
4. **DPLANEX 관점의 사업 시사점 도출** — 단순 뉴스 요약을 넘어 KANDLE, AI Studio, 관계사 AX 지원 관점에서 활용 가능성과 사업 기회를 정리한다.
5. **주간 AI 인사이트 보고서 자동 생성** — 수집된 뉴스와 인사이트를 기반으로 전략기획팀이 정기적으로 공유할 수 있는 주간 보고서를 자동 생성한다.
6. **내부 시장 정보 자산 축적** — 일회성 리서치가 아니라 수집 기사, 요약, 태그, 유사 기사, 시사점, 보고서가 누적되는 내부 AI 시장 정보 자산을 구축한다.

## 10. 리스크

**비용 리스크**

- 비용은 데이터 수집 API 비용, LLM API 비용, AWS 인프라 비용으로 구분된다.
- 수집된 정보를 요약·분류하고 기사형 요약, 유사 기사 기반 인사이트, 주간 보고서를 생성하는 과정에서 LLM API 비용이 발생할 수 있다.
- MVP 단계에서는 수집 기사 수, 보고서 생성 빈도, 요약 길이, LLM 호출 횟수를 제한하여 월 1만 원 이하 수준에서 운영하는 것을 목표로 한다.

**기술 리스크**

- 데이터 소스별 제공 형식이 달라 수집·정제 로직을 각각 구성해야 한다.
- AI Agent, 생성형 AI, AX와 직접 관련성이 낮은 정보가 함께 수집될 수 있어 키워드, 분류 기준, 필터링 로직의 고도화가 필요하다.
- 동일한 뉴스가 여러 출처에서 반복 수집될 가능성이 있으므로 중복 제거와 유사 기사 그룹핑 로직이 필요하다.
- 보고서 생성 결과가 원문 내용을 과도하게 해석하지 않도록 출처 기반 요약 기준과 프롬프트 관리가 필요하다.

**보안·운영 리스크**

- API Key, LLM Key 등 인증 정보가 외부에 노출되지 않도록 Secret 관리가 필요하다.
- 수집 데이터는 공개 자료 기반이지만, 내부 코멘트·DPLANEX 관점 시사점·활용 메모가 추가될 경우 접근 권한 관리가 필요하다.
- 정기 실행과 안정적인 운영을 위해 사내 개발 환경에서 먼저 검증한 뒤 Internal System AWS 기반 운영 환경으로 이관하는 절차가 필요하다.

**품질 리스크**

- LLM이 생성한 요약과 시사점이 항상 정확하다고 볼 수 없기 때문에 원문 URL과 출처를 함께 제공해야 한다.
- 초기 단계에서는 전략기획팀이 결과물을 직접 검토하며 분류 기준, 프롬프트, 보고서 템플릿을 개선하는 과정이 필요하다.
